# 哈基米四层记忆 · AstrBot

给 QQ 私聊机器人用的、有原文依据的长期记忆插件。原文即时落盘，本地 Ollama 生成检索向量，独立 API 整理事件与当前事实，另一个可独立配置的 API 写私密日记。

**首次公开测试版 v1.0.1。默认关闭采集，必须先配置目标私聊和管理账号。**

## 功能与存储

| 内容 | 用途 | 更新方式 |
|---|---|---|
| 原始记录底座 | 原话、时间、说话人、消息ID | 收到时写入 SQLite；过滤部分明显密钥格式 |
| L0 场景锚点 | 定位片段和话题 | 稳定消息生成时间与原文锚点，API可补充关键锚点 |
| L1 原文切片 | 保留上下文并支持找回原话 | 稳定约四秒后切片，异步建立向量 |
| L2 事件时间线 | 经历、约定、变化和未完成话题 | API增量整理，并关联来源 |
| L3 当前事实 | 当前偏好和计划等明确事实 | API或手动指令更新，保留旧版本 |

- Ollama **计算向量**，本插件**保存原文、向量和索引**。向量不替代文字。
- 普通整理每十轮，或有新消息且空闲十分钟触发；“记住、更正、不再、改为”等变化表达优先排队。
- API整理与本地索引分别运行，整理慢不会挡住原文保存和索引维护。失败任务持久化并退避重试。
- 本轮检索使用向量与关键词融合，最多六条，超时使用关键词和当前事实。临时记忆不反复写回聊天历史。
- 私密日记每天 **UTC+8 凌晨03:00** 处理前一天，启动补写；没有聊天的日期不编造经历，默认不主动发送。
- 成长只允许称呼习惯、吐槽尺度、口头禅、兴趣表达，保留依据并可撤销；不自动改写核心人格。
- 支持 TurnFlow 已完成轮次标记与主动消息伪事件标记，避免将取消回复、模拟触发提示当成真实经历。

## 适用环境

- AstrBot **4.29.1 或更高兼容版本**，首次开发与真实 SDK 测试环境为4.29.1。
- 当前支持范围为 **OneBot v11 / aiocqhttp 私聊、一个目标账号、一个绑定人格**。群聊不启用，其他平台未宣称兼容。
- Python3.10+，SQLite须支持 FTS5 trigram 和 JSON 函数。SQLite不支持相关功能时应升级Python/SQLite，而非删除数据重试。
- 已运行的 Ollama，以及 `bge-m3` 或兼容的文字嵌入模型；另需可用的聊天模型供整理和日记使用。
- 容器部署时，Ollama地址应指向容器可访问的服务；容器内 `127.0.0.1` 只代表该容器。

## 安装

1. 在运行 Ollama 的电脑上准备模型：

   ```sh
   ollama pull bge-m3
   ```

2. 在 AstrBot WebUI → 插件 → 从链接安装，填写：

   ```text
   https://github.com/missionary0326/astrbot_plugin_hakimi_memory
   ```

3. 在 AstrBot 模型提供商中添加所需的聊天API。记忆整理和日记可以使用同一个服务，也可以分别使用不同地址、模型和密钥。
4. 打开插件配置，完成下表后开启 `enabled`，保存并按页面提示重载插件。

| 配置项 | 填什么 |
|---|---|
| `owner_uid` | 允许记录和管理记忆的用户UID |
| `target_umo` | 指定私聊的完整UMO，通过 `/sid` 获得；必须是 FriendMessage |
| `persona_id` | 该私聊绑定的人格ID，精确一致，默认 `default` |
| `summary_provider_id` | 用于整理记忆的聊天模型 |
| `diary_provider_id` | 用于写日记的聊天模型 |
| `diary_persona_prompt` | 可选，只影响日记表达的人物设定；不改变AstrBot人格 |
| `ollama_url` | Ollama服务地址，默认 `http://127.0.0.1:11434` |
| `embedding_model` | 默认 `bge-m3`；切换模型后自动重建向量 |
| `data_dir` | 留空使用AstrBot插件数据目录 |
| `ollama_executable` | 通常留空；需要插件尝试启动本机服务时才填写程序路径 |

插件不会自动安装 Ollama 或下载模型，也不会内置任何API密钥。留空的整理/日记接口不自动借用其他接口；原文和本地索引仍可保留。

启用后正常聊天即可，无需每次手动保存、整理。可发送 `/记忆 状态` 查看运行情况。

## 管理指令

仅配置的私聊账号可管理本库：

| 指令 | 功能 |
|---|---|
| `/记忆 状态` | 查看原文、各层、向量和后台任务 |
| `/记忆 搜索 关键词` | 搜索并显示记忆编号 |
| `/记忆 来源 编号` | 核对对应原话 |
| `/记忆 记住 内容` | 立即保存明确指定的事实 |
| `/记忆 修正 编号 新内容` | 更新当前事实，保留旧版本 |
| `/记忆 忘记 编号` | 清理本库关联来源副本、记忆、向量及受影响日记 |
| `/记忆 整理` | 主动将新消息加入整理队列 |
| `/记忆 日记 [YYYY-MM-DD]` | 查看或请求生成指定日期的日记，默认今天 |
| `/记忆 成长` | 查看当前习惯 |
| `/记忆 撤销成长` | 回滚上次生效的成长 |
| `/记忆 暂停成长` / `/记忆 恢复成长` | 暂停或恢复自动成长 |
| `/记忆 暂停整理` / `/记忆 恢复整理` | 暂停或恢复自动高层整理 |

提供 `hakimi_memory_search` 模型工具，用于主动查找本私聊的记忆及来源。

## 日记、成长和 Obsidian

日记是机器人对实际聊天的第一人称感想，不作为用户事实来源。未提供日记角色设定时采用自然平实的表达，不强加特定名称、人设或模型品牌。

成长需要至少三个独立用户轮次的依据、累计二十轮完成回复，每天最多自动生效一次；核心身份不自动变化。明确纠正仍应优先尊重当前用户表达。模型归纳可能出错，可使用来源、修正和回滚指令检查。

数据目录下的 `Obsidian` 文件夹可直接作为笔记仓库打开：

- `00_场景锚点` 到 `05_成长记录` 为自动导出，直接编辑可能被覆盖。
- 将自己的 Markdown 放进 **手工笔记**，插件每分钟增量检查，更新或删除对应索引。
- 手工笔记标记为外部资料，不自动当作用户事实或日记共同经历。
- 本插件直接维护一套索引，不需要另外安装Obsidian同步插件。

## 数据、备份与限制

正式数据源为本地 `memory.sqlite3`。每日备份保留七天，向量可由原文重建。

“忘记”会清理本库对应来源副本及关联记忆，并在独立 `遗忘记录.json` 中保留来源ID。旧备份可能仍包含原文直到保留期结束；恢复旧数据库时必须保留该遗忘记录，启动会重放清理。它不会删除QQ、AstrBot或其他插件保存的原聊天。

原文与检索在本地，但整理和日记会将相应文本发送到你选择的API；检索出的相关记忆也会随聊天请求发送到聊天模型。明显密钥过滤只是辅助，不能保证识别所有敏感内容。请只启用你愿意记录的私聊，妥善保管本地数据库、Markdown和备份。

已在独立测试中验证来源隔离、重启、纠错、遗忘、回滚、慢API与索引分离，以及真实Ollama/API整理、日记和记忆回答。未宣称已完成长期真实QQ使用、跨自然日运行或其他平台的全部验证。首次公开版本建议先在自己的测试机器人上使用。

当前未自动提交AstrBot插件市场；可直接使用仓库链接安装。
